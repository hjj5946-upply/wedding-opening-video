## 진행 규칙 (무인 진행)
- 나는 자리를 비우니 중간에 질문하거나 승인을 기다리지 말고, 아래 전체(0~8번)를 처음부터 끝까지 한 번에 완료해 줘.
- 애매한 부분은 가장 합리적인 쪽으로 정하고 계속 진행해. 정한 내용은 완료 보고의 "임의로 정한 값"에 적어 줘. 되돌릴 수 없는 위험한 작업(저장소 삭제, 강제 푸시 등)만 하지 마.
- 만약 P02 의 E단계가 아직 끝나지 않았다면 E단계를 먼저 마무리하고 이어서 진행해.
- 단계별(1: 타임라인/멘트, 2: 맵/상자/사진, 3: 음악/효과음/비프음, 4: 신부 만남/엔딩/문서)로 작업하고, 각 단계가 끝날 때마다 npm run check 와 npm run build 를 통과시킨 뒤 커밋해. 마지막에 전체를 push 해.
- 사진 파일, 일부 모션 프레임 등 내가 아직 준비하지 못한 재료는 임시 표시로 대체해서 화면이 끝까지 돌아가게 해.
- 중간에 막히면(예: 오디오 디코딩 문제) 대안을 시도하고, 그래도 안 되면 그 부분만 기본값/임시로 처리하고 이유를 보고서에 적어 줘. 전체를 멈추지는 마.

이번 작업의 목표:

(다) 말풍선 비프음을 글자마다 나게 변경
(라) 피아노 이미지 교체, 신부 만남 이후 연출과 엔딩 정리

## 1. 전체 길이 (가장 중요)
- 지금 게임 진행 구간이 너무 길고 지루해. 영상 전체 목표는 100초 안팎, 상한 110초.
- 게임 진행 구간(GAME START ~ 깃발 터치)은 약 35~40초 이내로 압축해.
- 새 타임라인을 config 에서 짜고, npm run check 로 검증해. 완료 보고에 장면별 시작/끝 시각 표를 넣어 줘.

## 2. 피아노 장면
- 피아노 장면 멘트는 "처음 초안 버전"으로 되돌려 줘:
  P1 "첫 직장에 취직하고, 퇴근 후 취미로 피아노 학원에 등록했어요."
  P2 "그런데 거기서... 아주 아름다운 선생님을 만났습니다."
  (기존 config 에 있던 "작업만 쳤습니다" 등은 아래 게임 구간 멘트로 옮김)
- 코드로 그린 피아노를 grandPiano.png 로 교체해. image-rendering: pixelated, 비율 유지, 겹침 없게 위치/크기를 조정해. 신랑이 피아노를 치는 듯한 위치를 우선하고, 어색하면 보고해 줘.

## 3. 게임 진행 구간 (슈퍼마리오 스타일)
원작의 이미지·캐릭터·로고 파일은 쓰지 말고, 같은 스타일로 직접 도트로 그려 줘. 코드로 그리는 지금 방식 유지.
- 하늘색 배경, 구름, 언덕, 덤불, 벽돌 무늬 땅, 물음표상자(?), 벽돌, 초록 파이프, 계단, 깃발 등 슈퍼마리오 스타일 맵 소품. 적 캐릭터는 넣지 마.
- 신랑은 화면 왼쪽에 고정, 맵이 오른쪽에서 왼쪽으로 흐름(기존 방식).
- 물음표상자 8개: 각각 1년, 2년 ... 8년을 의미. 신랑이 점프해서 아래에서 머리로 치는 순간(apexAt 방식으로 시각 지정):
  · 상자가 위로 살짝 튀었다 내려오고, 칸이 빈 상자(갈색)로 바뀜
  · 하트가 뿅뿅 튀어나옴 (+ 짧은 팝 효과음, WebAudio 로 생성, 저작권 있는 샘플 사용 금지)
  · 해당 연도의 사진 한 장이 화면에 팝업(픽셀 액자 프레임, 작게 커졌다가 약 1.5초 유지 후 사라짐). 말풍선·HUD·신랑을 가리지 않는 위치(상단 우측 쪽)에 둬.
  · HUD 의 TIME 이 1 YEAR → 8 YEAR 로 올라감
- 사진 경로: public/assets/photos/year1.jpg ~ year8.jpg. 파일이 없으면 "1 YEAR" 같은 글자가 들어간 임시 프레임을 보여 줘서, 사진이 없어도 화면이 돌아가게 해. 사진 파일명/크기 권장(긴 변 1200px 이하 jpg)을 README 나 docs 에 적어 줘. 사진 목록은 config 에서 수정 가능하게.
- 낭떠러지(땅이 끊긴 구간) 1~2개: 신랑이 점프로 건너야 함. 떨어지지 않게(시각 지정 점프로 항상 성공). 하트는 안 닳음.
- 기존 글자 장애물(하트 감소)은 유지하되 시간 예산에 맞게 개수와 간격을 줄여: 최대 3개, 그중 2번 맞아 하트 2개가 닳는 연출.
- 물음표상자 위치·낭떠러지 위치·장애물 위치는 모두 시각(apexAt) 기반 config 로, 시킹(?t=) 시에도 정확히 나와야 해.
- 8년째 상자를 친 뒤: 계단(5~6단)이 나타나 신랑이 계단을 오르고, 꼭대기에서 점프해 깃발 기둥을 침 → 깃발이 내려오는 연출 → 맵이 멈춤. 이때 TIME 표시는 "8 YEAR 6 MONTH" 로 마무리.
- 이 구간에서 말풍선 위치는 상단 좌측 고정 영역 등으로 정해, 물음표상자/사진/HUD 와 겹치지 않게 해. 말풍선은 최대 2줄.

## 4. 게임 구간 멘트 (말풍선, 상자 1~8년이 진행되는 동안 순서대로 타이핑)
G1 "저는 피아노에만 집중하려고 했어요. 진짜예요. (진짜임)"
G2 "근데 쳐야 할 피아노는 안 치고... 선생님께 작업만 쳤습니다."
G3 "그리고 결국 선생님이 저에게 넘어왔습니다. 아니, 제가 넘어간...? 예.. 뭐, 그렇습니다."
G4 "아무튼 8년 6개월의 연애를 마치고, 이제 다음 챕터로 넘어가 보려 합니다."
G5 "앞으로의 길도 함께 잘 걸어갈 수 있다는 걸, 오늘 증명해 보이겠습니다." (초안, 내가 나중에 수정할 수 있음)
- 한 줄이 다 끝난 뒤에 다음 줄이 시작되게 해. 줄 시작 시각은 config 에서 수정 가능하게.
- 게임 구간의 타이핑 속도(cps)는 필요하면 올려서 시간 예산에 맞춰도 돼 (줄별 설정 가능하게).

## 5. 신부 만남 → 엔딩
- 깃발 연출 후 신랑이 땅으로 내려오고, 신부가 등장(깃발 근처). 신랑이 걸어가 만남.
- 만나는 순간 하트가 뿅 터지고, 지금 비어 있는 HUD 하트가 하나씩 차례로 3개 모두 다시 채워지는 연출 (채워질 때 짧은 효과음).
- 이어서 두 캐릭터가 인사하는 모션. 손 흔들기나 꾸벅 인사 등 현재 가진 프레임/코드 모션으로 처리하고, 부족한 모션은 임시로 표시했다고 보고해 줘.
- 이후 화면이 검정으로 페이드 아웃 → 검은 화면에서 마지막 감사 인사 문구(기존 config.closing)가 페이드 인/아웃으로 한 줄씩 → 마지막에 다시 완전한 검정으로 페이드 아웃하고 끝. (마지막 카드 문구를 쓰고 있었다면 그 구성도 이 흐름에 맞게 정리)

## 6. 음악과 효과음 (웹에서 직접 재생)
기존의 "음악은 편집 단계에서 입힘" 방침을 바꿔, 웹페이지 안에서 직접 재생하고 OBS 데스크톱 오디오로 함께 녹음할 거야. 음소거용 URL 옵션도 필요해.
- 트랙: intro(intro.mp3), mario(super_mario.mp3), walk(walk.mp3)
- 큐(시각은 모두 config.audio 에서 수정 가능, 트랙별 시작 오프셋(파일 내 시작 위치), 볼륨, 페이드 시간, 반복 여부 포함):
  · walk: 신랑이 걸어 들어오는 구간에만 재생, 멈추면 바로 끝(짧게 페이드). 파일이 걷는 구간보다 길면 자르고, 짧으면 반복.
  · intro: 신랑이 멈추고 첫 인사를 시작하는 시점부터 재생. 피아노 장면까지 이어지다가 GAME START 직전에 짧게 페이드 아웃.
  · mario: GAME START 시점부터 재생(필요하면 반복). 깃발을 치는 시점에 페이드 아웃(약 1.5초).
  · 엔딩 감사 인사 구간: intro 트랙을 낮은 볼륨으로 다시 페이드 인해서 재생(옵션, config 에서 켜고 끌 수 있게, 기본은 켬).
- 믹스: BGM 이 말풍선 비프음과 효과음을 덮지 않도록 기본 볼륨을 정해 줘(측정한 평균 음량을 근거로). 마스터 볼륨과 트랙별 볼륨을 config 에 둬.
- 동작:
  · 스페이스바로 시작할 때 오디오가 시작(브라우저 자동재생 제한 회피).
  · ?t= 시킹, ←/→ 이동, 숫자키 장면 이동, P 일시정지 시에도 음악이 현재 시각에 맞게 따라가고(재동기화), 일시정지하면 멈추고 다시 재생하면 이어가게.
  · R 로 처음으로 돌아가면 오디오도 처음부터.
  · ?music=0 → BGM/발걸음 음소거, ?sfx=0 → 효과음(비프음 등) 음소거, ?mute=1 → 전부 음소거.
  · 정확도를 위해 Web Audio(디코딩한 버퍼 + 시작 시각/오프셋 예약)를 쓰고, HTMLAudio 의 지연/끊김 문제가 있으면 알려 줘.
- 무거운 처리는 피하고 60fps 유지(오디오 디코딩은 시작 전에 미리 완료, 로딩 중에는 "SPACE" 안내를 띄우지 말고 준비되면 표시).

## 7. 말풍선 비프음 (동물의 숲 스타일)
- 글자 하나하나가 나올 때마다 짧은 비프음(뿅)이 나게 해. config.sfx.blipEveryNChars 를 1, 문장당 제한(blipMaxPerLine)은 해제(null 또는 큰 값).
- 공백과 문장부호에서는 소리를 내지 않음. 글자마다 피치를 아주 조금(±몇 %) 랜덤으로 흔들어 단조롭지 않게 해. 신랑/신부는 기본 피치를 다르게.
- 소리가 겹쳐 지직거리거나 성능이 떨어지지 않게 노드 수 제한과 짧은 엔벨로프를 써.
- 빠른 타이핑(cps 높음)에서도 듣기 좋게, 최소 소리 간격을 config 로 조절 가능하게.

## 8. 마무리
- 마지막에 npm run check, npm run build 통과 확인. 스크린샷(?t= 로 주요 장면)을 찍어서 눈으로 확인하고 문제가 있으면 직접 고쳐 줘: 인사 장면, 피아노 장면, 게임 중(상자 치는 순간 + 사진 팝업 + 말풍선 동시에), 낭떠러지, 계단/깃발, 신부 만남 + 하트 채움, 마지막 감사 인사. 글자·말풍선·사진이 서로 겹치거나 잘리는 곳이 없어야 해.
- 해상도 1920×1080, 60fps 유지 여부를 점검하고, 위험 요소가 있으면 알려 줘.
- docs 갱신: 02_SCENARIO.md(장면표/멘트/음악 큐), 03_DECISIONS.md(음악을 웹에서 직접 재생하는 것으로 변경, 피아노 멘트 원복, 게임 구간 압축 등), 04_RECORDING_GUIDE.md(OBS 데스크톱 오디오로 소리까지 녹음, 편집 툴에서는 앞뒤 자르기/페이드/내보내기만), PROGRESS.md, CLAUDE.md 필요 시.
- 전체를 push 하고, 마지막 메시지에 아래를 한국어로 쉽게 정리해 줘:
  1) "푸시 완료"와 마지막 커밋 메시지
  2) 장면별 시작/끝 시각 표와 전체 길이
  3) 만든 것 요약(단계별)
  4) 임의로 정한 값 목록(내가 바꿀 수 있는 것)
  5) 임시로 처리한 것(사진, 신부 인사 모션 등)과 확인하지 못한 것
  6) 내가 돌아와서 직접 확인할 것(재생 방법, 볼 포인트)
